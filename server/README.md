# VibeWake relay

A small server that connects VibeWake on your Macs to the Android app. Both sides connect out to it over WebSockets, so neither the Macs nor the phone need to be reachable. It keeps commands the phone sends to a sleeping Mac until that Mac checks in, and forwards events (chat finished, usage limit, waiting for input) as push notifications through [ntfy](https://ntfy.sh).

It is a single [Bun](https://bun.sh) process with a SQLite file. The message format is in [../protocol/PROTOCOL.md](../protocol/PROTOCOL.md).

## Run it

```bash
cd server
cat > .env <<'ENV'
SETUP_CODE=<a long random string, e.g. from: openssl rand -base64 24>
NTFY_BASE_URL=https://ntfy.example.com
ENV
docker compose up -d --build
```

This starts the relay on `127.0.0.1:3030` and ntfy on `127.0.0.1:3031`. Put both behind your HTTPS reverse proxy. With Caddy:

```
relay.example.com {
    reverse_proxy 127.0.0.1:3030
}
ntfy.example.com {
    reverse_proxy 127.0.0.1:3031
}
```

`docker-compose.yml` sets `TRUST_PROXY=1`, so the relay takes the client IP for rate limits from the last `X-Forwarded-For` entry (which Caddy and nginx's `$proxy_add_x_forwarded_for` set). Behind Cloudflare that entry is a Cloudflare edge, so the relay then uses Cloudflare's `CF-Connecting-IP` instead — only when the request came from a Cloudflare address, so the header can't be forged by going around Cloudflare. No proxy config is needed for this. Only set it when the relay is reachable through the proxy alone: exposed directly, anyone can send that header and dodge the rate limit.

WebSockets need no extra proxy settings in Caddy. With nginx, add `proxy_http_version 1.1`, plus the `Upgrade` and `Connection` headers, and a `proxy_read_timeout` above 90 s.

If you already run ntfy, drop the `ntfy` service from `docker-compose.yml` and point the ntfy app on your phone at your existing server.

## Connect

1. **Mac:** VibeWake menu → **Show Agents…** → **Phone app**. Enter `https://relay.example.com` and the `SETUP_CODE`, then **Connect**. Or run `VibeWake remote setup https://relay.example.com <SETUP_CODE>`.
2. **Phone:** install the [ntfy app](https://ntfy.sh/docs/subscribe/phone/). In its settings, set the default server to `https://ntfy.example.com`.
3. **Pair:** on the Mac, click **Pair Phone…** and scan the QR code with the VibeWake app. The code works once and expires after 5 minutes.

Pair each phone once; it then sees every Mac registered with the relay. Unpairing in the app calls `DELETE /api/device`, which deletes that phone's token and push endpoint. To remove a Mac, run `VibeWake remote off` on it and call `DELETE /api/machines/<id>` with a phone's token (the relay then rejects that Mac's token).

## Security

- `SETUP_CODE` is what allows a Mac to register. Anyone who has it can register a Mac. Only a paired phone can send commands, and pairing needs a code generated by an already registered Mac.
- Tokens are 32 random bytes. The relay stores only their SHA-256 hash. Wrong setup or pairing codes are rate-limited to 10 per client IP per 10 minutes (behind a proxy this needs `TRUST_PROXY=1`, or all clients share the proxy's IP).
- A paired phone can make Claude run prompts on your Macs. Treat the phone like a key to them. To limit what it can do on a Mac, turn off **Allow remote control** in that Mac's Phone app bar. The phone can still watch, but nothing else.
- The relay stores the latest snapshot of each Mac (chat titles, folders, queued prompts, the first 8 KB of replies) and the last week of commands.
- Push endpoints must be `https` URLs and not point at `localhost` or a loopback, private or link-local IP address, so a phone can't make the relay call into its own network. The relay doesn't follow redirects from them. Set `ALLOW_HTTP_PUSH=1` to also accept `http` (e.g. `http://ntfy/...` inside the compose network; private IP addresses stay blocked). Host names aren't resolved, so a name that points at a private address is still accepted.
- Push notifications contain the chat title and up to 300 characters of the reply, sent unencrypted to ntfy. UnifiedPush topics are random. To lock ntfy down: set `auth-default-access: deny-all` on the ntfy server, allow anonymous writes only to `up*` topics with `ntfy access everyone 'up*' write-only`, and log in from the ntfy app.

## Develop

```bash
bun install
SETUP_CODE=dev-setup-code-123 bun run dev   # http://localhost:8080
bun test
bun run typecheck
```

No Bun installed? `docker run --rm -v "$PWD":/app -w /app oven/bun:1-alpine sh -c "bun install && bun test"`.
